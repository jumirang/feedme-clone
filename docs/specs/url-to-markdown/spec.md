# FEED-ME: URL → Markdown 변환기

웹 페이지 URL을 붙여넣으면 본문을 Markdown으로 뽑아 보여주고, 복사·다운로드하거나 ChatGPT·Claude에 프롬프트와 함께 바로 넘길 수 있는 단일 화면 서비스입니다.

## 관련 소스

- [prototype.html](prototype.html) — 승인된 화면. 화면 구성, 요소 배치와 순서, 문구, 상태별 모습(빈 상태, 로딩, 결과, 오류, 다크모드, 좁은 화면)은 이 파일을 따릅니다. 프로토타입 안의 더미 데이터, 상태 선택기(review bar), 간이 Markdown 렌더러, 임시 ChatGPT·Claude 아이콘은 구현 대상이 아닙니다.
- [docs/decisions/ui-composition.md](../../decisions/ui-composition.md) — 컴포넌트 선택, 색상·상태 표현의 기준. 프로토타입의 `data-component` 이름(InputGroup, ButtonGroup, DropdownMenu, Collapsible, ToggleGroup, Alert, Skeleton, Sonner 등)은 대응하는 shadcn 컴포넌트를 가리킵니다.
- [docs/decisions/dependency-versions.md](../../decisions/dependency-versions.md) — 새 의존성(`defuddle`, DOM 구현체, Markdown 렌더러)을 추가할 때의 버전 기준.
- defuddle 문서: https://defuddle.md/docs

## 사용자가 얻는 결과

- URL 하나로 웹 페이지 본문을 광고·메뉴 없는 Markdown으로 얻습니다.
- 결과를 화면에서 제목·저자와 함께 읽기 좋게 확인합니다.
- 한 번의 클릭으로 Markdown을 복사하고, 메뉴에서 `.md` 파일로 받습니다.
- 메뉴에서 ChatGPT 또는 Claude 새 대화를 열고, 원하면 "요약해줘" 같은 프롬프트를 본문 앞에 붙여 넘깁니다.
- 라이트·다크 테마를 전환합니다.

## 범위

### 1. 첫 화면과 입력

- 상단에 서비스 이름 **FEED-ME**와 부제 "어떤 URL이든, Markdown으로."를 보여줍니다.
- 테두리 박스 하나 안에 URL 입력, 지우기(✕) 버튼, 구분선, 변환(→) 버튼이 있습니다. Enter로도 변환합니다.
- 지우기 버튼은 입력값이 있을 때만 보입니다. 누르면 입력값, 변환 결과, 오류, 프롬프트 선택을 모두 처음 상태로 되돌리고 입력에 포커스를 둡니다.
- `http://` 또는 `https://`로 시작하는 URL만 받습니다. 그 외 입력은 변환하지 않고, 박스를 오류 색으로 표시하고 그 아래에 형식 오류 문구를 보여줍니다. 다시 입력하면 오류 표시가 사라집니다.
- 아직 변환한 적이 없으면 결과 자리에 "변환한 페이지가 여기에 나타납니다" 안내를 보여줍니다.

### 2. 변환

- 페이지 HTML은 서버에서 가져옵니다(브라우저에서 다른 사이트를 직접 가져오면 CORS로 막히기 때문).
- 본문 추출과 Markdown 변환은 반드시 `defuddle` 라이브러리로 합니다(`markdown: true`). 호스팅 API(`defuddle.md/<url>`)는 쓰지 않습니다.
- 변환 중에는 변환 버튼의 화살표가 스피너로 바뀌고 버튼이 비활성이 되며, 결과 자리에 스켈레톤이 보입니다. 변환 중 같은 요청을 다시 보낼 수 없습니다.
- 실패하면 결과 자리에 오류 알림(제목 + 설명)을 보여주고, 입력값은 그대로 남겨 다시 시도할 수 있게 합니다. 구분하는 실패는 다음과 같습니다.
  - 페이지를 가져오지 못함(네트워크 오류, 4xx/5xx 응답, 시간 초과)
  - HTML이 아닌 응답(PDF, 이미지 등)
  - 추출된 본문이 비어 있음

### 3. 결과 확인

- 구분선 아래에 페이지 제목을 크게 보여주고, 그 아래 `By {저자}` 줄을 둡니다.
  - 저자가 없으면 `By` 줄을 숨깁니다. 제목이 없으면 원본 URL의 도메인을 제목 자리에 씁니다.
  - 결과 헤더에는 원본 URL 링크를 따로 표시하지 않습니다(입력란에 남아 있음).
- 제목 아래 오른쪽에 내보내기 분할 버튼, 왼쪽에 프롬프트 추가 토글이 있습니다(4, 5절).
- 그 아래 구분선 다음에 Markdown을 렌더링한 본문(제목, 목록, 링크, 코드 블록, 표, 인용, 이미지)을 보여줍니다.
- 새 URL로 다시 변환하면 이전 결과를 대체하고 프롬프트 선택도 초기화합니다.

### 4. 내보내기

내보내기 대상인 "Markdown 문서"는 다음 순서로 구성합니다.

```
# {제목}

> 출처: {원본 URL}
> 저자: {저자}        ← 저자가 있을 때만

{defuddle이 만든 Markdown 본문}
```

내보내기는 **복사하기 | ⌄** 분할 버튼 하나로 묶습니다.

- **복사하기**(주 버튼): Markdown 문서를 클립보드에 복사하고, 버튼 문구를 잠시 "복사했습니다"로 바꿨다가 되돌립니다. 프롬프트는 붙이지 않습니다. 복사가 실패하면 오류 토스트를 보여줍니다.
- **⌄**(메뉴 열기): 아래 세 항목이 있는 메뉴를 엽니다. 메뉴 바깥을 클릭하거나 Esc를 누르면 닫히고, 항목을 고르면 닫힙니다.
  - **마크다운 다운로드**: Markdown 문서를 `{제목을 파일명에 안전한 형태로 바꾼 것}.md`로 내려받습니다. 제목이 없거나 바꾼 결과가 비면 `page.md`입니다. 프롬프트는 붙이지 않습니다.
  - **ChatGPT에서 열기 / Claude에서 열기**: 새 탭에서 해당 서비스의 새 대화를 엽니다. 보낼 텍스트는 프롬프트가 선택되어 있으면 `{프롬프트}\n\n{Markdown 문서}`, 아니면 Markdown 문서만입니다.
    - 보낼 텍스트를 URL 인코딩한 길이가 **한도 이하**면 `?q=` 파라미터에 담아 엽니다.
      - ChatGPT: `https://chatgpt.com/?q={인코딩된 텍스트}`
      - Claude: `https://claude.ai/new?q={인코딩된 텍스트}`
    - **한도를 넘으면** 보낼 텍스트 전체(프롬프트 포함)를 클립보드에 복사하고, 해당 서비스의 새 대화를 `?q=` 없이 엽니다. 동시에 "본문이 길어 클립보드에 복사했습니다. 새 탭의 {서비스} 입력란에 붙여넣기(Ctrl+V / ⌘V) 하세요" 토스트를 보여줍니다.
    - 클립보드 복사가 실패하면 새 탭을 열지 않고 오류 토스트를 보여줍니다.
    - 한도는 URL 인코딩 후 8,000자입니다(가정 참고).

### 5. 프롬프트

- 결과 왼쪽의 **+ 프롬프트 추가하기 ›** 토글을 누르면 프리셋 칩 영역이 펼쳐지고(›가 아래로 회전), 다시 누르면 접힙니다.
- 칩: **요약해줘** / **한국어로 번역해줘** / **쉽게 설명해줘** / **직접 입력**. 한 번에 하나만 선택되고, 선택된 칩을 다시 누르면 선택이 풀립니다(프롬프트 없음). 기본값은 선택 없음입니다.
- 프롬프트가 선택되면 토글 문구가 "프롬프트: {선택한 프롬프트}"로 바뀝니다(길면 말줄임). 선택이 없으면 "프롬프트 추가하기"입니다.
- "직접 입력"을 선택하면 칩 아래에 텍스트 입력이 나타나 포커스를 받고, 선택을 풀거나 다른 칩으로 바꾸면 사라지며 내용도 지워집니다.
- 직접 입력한 프롬프트는 1회용입니다. 저장하지 않으며 새로고침, 지우기 버튼, 새 변환, 다른 칩으로 전환하면 사라집니다.
- "직접 입력"을 선택했지만 내용이 비어 있거나 공백뿐이면 프롬프트 없음으로 취급합니다.
- 프롬프트는 ChatGPT·Claude에서 열기에만 적용됩니다.

### 6. 다크모드

- 화면 오른쪽 위에 라이트/다크 전환 아이콘 버튼이 있습니다(라이트일 때 달, 다크일 때 해).
- 처음 방문하면 운영체제 설정을 따릅니다. 사용자가 토글로 고르면 그 선택을 브라우저에 기억해 다음 방문에도 유지합니다.
- 테마가 적용되기 전 잘못된 테마가 잠깐 보이는 깜빡임이 없어야 합니다.

### 7. 좁은 화면

- 390px 너비에서도 가로 스크롤 없이 모든 요소와 동작이 보입니다. 서비스 이름과 결과 제목은 작아지고 줄바꿈됩니다. 코드 블록과 표만 자체 가로 스크롤을 가집니다.

## 수용 기준

1. 첫 화면에 FEED-ME, 부제, URL 입력 박스, 빈 결과 안내가 보인다.
2. 위키피디아 문서 URL(예: `https://en.wikipedia.org/wiki/Markdown`)을 넣고 변환하면 제목 "Markdown"과 `By` 줄이 보이고, 아래에 렌더링된 본문(제목·링크·목록이 서식대로 보임)이 나온다.
3. 저자 정보가 없는 페이지(예: `https://example.com`)를 변환하면 `By` 줄이 보이지 않는다.
4. `ftp://a.b`나 `hello` 같은 입력은 서버 요청 없이 형식 오류를 보여준다.
5. 존재하지 않는 도메인이나 404 페이지를 변환하면 오류 알림이 보이고 입력값은 남아 있다.
6. 변환 중에는 변환 버튼이 스피너로 바뀌어 비활성이고 스켈레톤이 보인다.
7. 지우기 버튼을 누르면 입력, 결과, 오류, 프롬프트 선택(직접 입력 내용과 펼침 상태 포함)이 모두 초기 상태가 된다.
8. 복사하기를 누르면 클립보드에 `# {제목}`으로 시작하고 출처 줄과 본문이 이어지는 Markdown 문서가 들어가며, 버튼 문구가 잠시 "복사했습니다"로 바뀐다.
9. ⌄를 누르면 마크다운 다운로드 / ChatGPT에서 열기 / Claude에서 열기 메뉴가 열리고, 바깥 클릭이나 Esc로 닫힌다.
10. 마크다운 다운로드를 누르면 제목 기반 파일명의 `.md` 파일이 내려받아지고 내용은 8번의 Markdown 문서와 같다.
11. 짧은 페이지(인코딩 길이 8,000자 이하)에서 "요약해줘"를 고르고 Claude에서 열기를 누르면, 새 탭 URL이 `https://claude.ai/new?q=`로 시작하고 디코딩한 값이 "요약해줘"로 시작한 뒤 빈 줄 하나를 두고 Markdown 문서가 이어진다. ChatGPT에서 열기는 같은 조건에서 `https://chatgpt.com/?q=`로 시작한다.
12. 긴 페이지(인코딩 길이 8,000자 초과)에서 ChatGPT에서 열기를 누르면 클립보드에 프롬프트+문서 전체가 들어가고, 새 탭 URL에는 `q` 파라미터가 없으며, 붙여넣기 안내 토스트가 보인다.
13. 프롬프트 추가하기를 누르면 칩이 펼쳐진다. 칩을 고르면 토글 문구가 "프롬프트: …"로 바뀌고, 같은 칩을 다시 누르면 "프롬프트 추가하기"로 돌아간다.
14. "직접 입력"을 고르면 텍스트 입력이 나타나고 다른 칩으로 바꾸면 사라진다. 직접 입력한 내용은 새로고침 후 남아 있지 않다.
15. "직접 입력"이 비어 있는 상태에서 LLM으로 열면 프롬프트 없이 Markdown 문서만 보낸다.
16. 다크모드 버튼을 누르면 화면 전체와 아이콘이 즉시 전환되고, 새로고침 후에도 선택한 테마가 깜빡임 없이 유지된다. 선택 기록이 없을 때는 운영체제 설정을 따른다.
17. 390px 너비에서 결과 화면과 열린 메뉴가 가로 스크롤 없이 보인다.

## 확정된 제약과 이유

- **본문 추출은 `defuddle` 라이브러리로 한다.** 사용자가 필수로 지정했습니다. scratch에서 `defuddle@0.19.6` + `linkedom`을 Node에서 실행해 위키피디아·example.com·Hacker News에서 `title`, `author`, Markdown `content`가 나오는 것을 확인했습니다. `defuddle/node`는 ESM 전용이라 서버 쪽 사용 환경이 ESM import를 지원해야 합니다. defuddle이 라이브러리 형태 지원을 중단하거나 Node 사용 방식이 바뀌면 다시 봅니다.
- **긴 본문은 클립보드 폴백으로 넘긴다.** `?q=`에 담을 수 있는 길이에는 한도가 있어 긴 글을 그대로 실을 수 없습니다. 본문을 자르면 LLM이 글 일부만 보게 되고, 항상 복사만 하면 짧은 글에서도 붙여넣기가 필요합니다. 사용자가 이 셋 중 클립보드 폴백을 골랐습니다.
- **화면은 승인된 프로토타입을 따른다.** 사용자가 레퍼런스 이미지를 주고 그대로 만든 프로토타입을 승인했습니다. 내보내기는 복사하기 중심의 분할 버튼으로, 프롬프트는 접히는 칩 영역으로 둡니다.
- **프롬프트는 LLM으로 열기에만 붙인다.** 복사·다운로드 결과물은 원문 그대로의 문서여야 다른 용도로도 쓸 수 있습니다.
- **직접 입력 프롬프트는 저장하지 않는다.** 사용자가 1회용으로 지정했습니다.

## 가정 (구현 중 바꿀 수 있음)

- LLM 열기 한도는 URL 인코딩 후 8,000자입니다. 브라우저와 서비스 쪽 URL 한도를 넉넉히 밑도는 값으로 잡았습니다. 한글은 인코딩하면 글자당 9자가 되므로, 한국어 본문은 약 1,700자만 넘어도 폴백이 동작합니다. ChatGPT·Claude가 실제로 더 긴 `?q=`를 받아준다는 것이 확인되면 올려도 됩니다.
- ChatGPT `https://chatgpt.com/?q=`와 Claude `https://claude.ai/new?q=`가 대화 입력란을 미리 채워 준다고 가정합니다. 로그인 상태에서의 실제 동작은 확인하지 못했습니다.
- 서버의 페이지 요청 시간 초과는 15초로 둡니다.
- 화면 문구는 한국어입니다.

## 범위 밖

- 로그인이 필요한 페이지, JavaScript로만 본문을 그리는 페이지의 렌더링 후 추출 — 서버에서 받은 HTML만 다룹니다. 헤드리스 브라우저는 강의 템플릿 범위를 넘습니다.
- PDF·이미지 등 HTML이 아닌 문서의 변환 — 오류로 안내만 합니다.
- 변환 기록, 계정, 즐겨찾기 프롬프트 저장.
- defuddle 호스팅 API 사용 — 유료 키가 필요하고 사용자가 라이브러리를 지정했습니다.
- 요청 제한, SSRF 방어 같은 보안 하드닝 — 프로젝트 검증 예산상 스펙이 요구하지 않은 하드닝은 범위 밖입니다.
- 실제 ChatGPT·Claude 로고 에셋 — 상표 사용 여부를 따로 판단하지 않았으므로, 구현에서는 아이콘 라이브러리의 일반 아이콘이나 프로토타입 수준의 단순한 표식을 씁니다.

## 남은 위험

- 한국어 글은 대부분 8,000자 한도를 넘어 클립보드 폴백으로 넘어갑니다. 사용자는 붙여넣기를 한 번 더 해야 합니다.
- 일부 사이트는 서버발 요청을 봇으로 보고 막습니다(403, 캡차 페이지). 이 경우 오류가 나거나 엉뚱한 본문이 나올 수 있습니다.
- ChatGPT·Claude가 `?q=` 동작을 바꾸거나 없애면 짧은 글의 바로 넘기기가 빈 대화만 여는 동작으로 바뀝니다. 그때는 폴백과 같은 클립보드 방식으로 통일하면 됩니다.
- JavaScript로 렌더링하는 사이트(SPA)는 본문이 비거나 매우 짧게 나올 수 있습니다.
