# 변환한 글 저장과 저장한 글 목록

로그인한 사용자가 변환 결과를 직접 저장하고, 나중에 "저장한 글" 목록에서 다시 열어 같은 방식으로 내보낼 수 있게 합니다.

## 연결된 출처

- [docs/decisions/url-to-markdown-conversion.md](../../decisions/url-to-markdown-conversion.md) — 저장한 글을 다시 열었을 때의 내보내기(복사, `.md` 다운로드, ChatGPT·Claude 열기, `?q=` 한도와 클립보드 폴백, 프롬프트 처리)를 그대로 따릅니다.
- [docs/decisions/ui-composition.md](../../decisions/ui-composition.md) — 저장 버튼, 목록·상세 화면, 빈 상태·오류 상태의 구성 규칙을 따릅니다.

## 사용자가 얻는 결과

- 변환 결과 화면에서 "저장"을 누르면 그 글이 내 계정에 남습니다.
- "저장한 글" 목록에서 내가 저장한 글을 최신순으로 볼 수 있습니다.
- 목록에서 글을 열면 다시 변환하지 않고 저장된 본문을 읽을 수 있고, 변환 직후와 똑같이 복사·다운로드·ChatGPT/Claude로 열기를 쓸 수 있습니다.

## 범위

포함:
- 변환 결과 화면의 저장 버튼
- 로그인 사용자 전용 "저장한 글" 목록 화면과 글 상세 화면
- 어느 화면에서든 목록으로 가는 진입점

제외(이유):
- 저장한 글 삭제, 검색, 정렬 변경, 태그 — 요청에 없고, 저장을 직접 고르는 방식이라 목록이 원치 않는 글로 채워질 위험이 낮습니다.
- 저장본을 원본 URL에서 다시 변환해 갱신하는 기능 — 같은 URL을 다시 변환해 저장하면 같은 결과를 얻습니다.
- 다른 사용자와 공유, 공개 링크 — 저장한 글은 본인만 봅니다.
- 요청 제한, 저장 용량 제한 같은 하드닝 — 학습 템플릿의 검증 예산 밖입니다.

## 수용 기준

1. 로그인한 상태에서 URL을 변환하면 결과 화면의 기존 액션(복사하기, 더 보기)과 같은 줄에 "저장" 버튼이 보입니다.
2. "저장"을 누르면 성공 피드백이 보이고, 그 글이 "저장한 글" 목록 맨 위에 나타납니다.
3. 같은 URL을 다시 변환해 저장하면 목록에 항목이 하나 더 생기지 않고, 기존 항목이 최신 변환 결과(제목·저자·본문)로 바뀌며 맨 위로 올라옵니다.
4. 로그인하지 않은 상태에서도 변환은 지금처럼 동작합니다. 이때 "저장"을 누르면 로그인 화면으로 이동하고, 로그인 뒤에는 "저장한 글" 목록으로 돌아옵니다. 방금 변환한 글은 저장되지 않으며 다시 변환해야 합니다.
5. 로그인하지 않은 사용자가 목록이나 상세 화면 주소로 직접 들어가면 로그인 화면으로 이동하고, 로그인 뒤 원래 주소로 돌아옵니다.
6. 목록의 각 항목에는 제목(없으면 원본 호스트명), 원본 URL의 호스트, 저장 일시가 보입니다. 저장한 글이 없으면 빈 상태 안내와 변환 화면으로 가는 링크가 보입니다.
7. 항목을 열면 저장 시점의 제목, 저자, 원본 링크, 마크다운 본문이 변환 결과 화면과 같은 모양으로 보이고, 복사하기·마크다운 다운로드·ChatGPT/Claude에서 열기·프롬프트 선택이 변환 직후와 같은 결과를 냅니다.
8. 원본 페이지가 바뀌거나 사라져도 저장한 글의 내용은 바뀌지 않습니다.
9. 사용자 A가 저장한 글은 사용자 B의 목록에 나오지 않고, B가 A의 글 상세 주소로 들어가도 내용을 볼 수 없습니다(찾을 수 없음 안내).
10. 저장에 실패하면 오류 피드백이 보이고 화면의 변환 결과는 그대로 남아 다시 시도할 수 있습니다.

## 확정된 제약과 근거

- **저장은 사용자가 "저장" 버튼을 눌렀을 때만 합니다.** 변환은 URL을 가볍게 확인하는 용도로도 쓰이므로, 자동 저장하면 목록이 원치 않는 글로 채워지고 삭제 기능이 사실상 필수가 됩니다. 사용자가 확인했습니다.
- **저장은 로그인 사용자 전용이고, 저장한 글은 본인만 읽고 쓸 수 있습니다.** 기존 `profiles`와 같은 소유자 전용 접근 규칙을 따릅니다.
- **변환은 계속 로그인 없이 쓸 수 있습니다.** 저장 기능 때문에 기존 변환 흐름을 막지 않습니다.
- **프롬프트는 저장하지 않습니다.** 직접 입력한 프롬프트는 1회용이라는 기존 결정을 따릅니다.

## 가정 (덮어쓸 수 있음)

- 저장 대상은 변환 시점의 원본 URL, 제목, 저자, 마크다운 본문이며 원본이 바뀌어도 고정된 사본으로 둡니다.
- 같은 사용자 안에서 같은 원본 URL은 한 항목으로 취급합니다(URL 문자열 그대로 비교, 정규화는 하지 않음).
- 목록 진입점은 페이지 상단의 "저장한 글" 링크로 둡니다. 로그인 상태가 아니어도 보이며, 누르면 수용 기준 5대로 로그인으로 이어집니다.
- 목록은 페이지 나누기 없이 전체를 보여 줍니다. 학습용 규모에서 문제가 되지 않는다고 봅니다.
- 별도 프로토타입 없이 기존 변환 결과 화면의 구성과 `ui-composition` 계약을 따릅니다. 새 화면은 목록 하나와 기존 결과 화면을 재사용하는 상세 하나뿐이라 화면 단위 시각 결정이 따로 필요하지 않다고 판단했습니다.
- 비로그인 저장 시 변환 결과를 보존해 로그인 후 자동 저장하지 않습니다. 구현이 단순하고, 다시 변환하면 같은 결과를 얻기 때문입니다.

## 손대지 않는 영역

- 변환 방식, LLM 내보내기 규칙, `?q=` 한도 — `url-to-markdown-conversion` 계약의 영역이며 이번 작업은 그대로 재사용만 합니다.
- 로그인·회원가입·설정 화면의 동작 — 로그인 뒤 돌아올 주소를 넘기는 기존 방식만 사용합니다.

## 남은 위험

- 같은 URL 판정을 문자열 그대로 하므로 `?utm_...` 같은 쿼리나 끝 슬래시만 다른 주소는 별개 항목이 됩니다. 삭제 기능이 없어 이런 중복을 사용자가 지울 수 없습니다.
- 삭제 기능이 없어 실수로 저장한 글이 목록에 남습니다. 불편이 보고되면 삭제를 다음 작업으로 다룹니다.
- 본문이 아주 긴 글도 그대로 저장하므로 저장 용량이 커질 수 있지만 학습 템플릿 범위에서는 다루지 않습니다.
